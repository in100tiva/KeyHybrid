# Suporte

O KeyHybrid é mantido por uma pessoa só, então o caminho mais rápido para resolver alguma coisa é escolher o canal certo:

| O que você precisa | Onde ir |
| --- | --- |
| Dúvida de uso, "como faço para…" | [Discussions › Q&A](https://github.com/in100tiva/KeyHybrid/discussions/categories/q-a) |
| Ideia de recurso, feedback | [Discussions › Ideas](https://github.com/in100tiva/KeyHybrid/discussions/categories/ideas) ou uma [issue](https://github.com/in100tiva/KeyHybrid/issues/new/choose) |
| Bug reproduzível | [Abrir issue](https://github.com/in100tiva/KeyHybrid/issues/new/choose) com o template de bug |
| Falha de segurança | **Não abra issue.** Use o [advisory privado](https://github.com/in100tiva/KeyHybrid/security/advisories/new) — detalhes em [SECURITY.md](../SECURITY.md) |
| Instalação e primeiros passos | [docs/INSTALL.md](INSTALL.md) e [docs/USAGE.md](USAGE.md) |
| Contribuir com código | [CONTRIBUTING.md](../CONTRIBUTING.md) |

## Antes de abrir um chamado

1. Confira a [documentação](../docs/index.md) e as [duas perguntas do README](../README.md) — a maioria das dúvidas é sobre "onde ficam minhas chaves".
2. Rode `keyhybrid-server --version` e inclua a saída no relato.
3. Em bugs, diga o sistema operacional, como você instalou (binário da release, `docker compose` ou compilando) e o passo a passo para reproduzir.

## O que tenho disponibilidade para responder

- Bugs e problemas de segurança: prioridade.
- Dúvidas de uso: respondidas nas Discussions, geralmente em alguns dias.
- Pedidos de recurso: entram na discussão; o que for aceito vira issue com milestone.

## Escopo de suporte

O projeto está em `v0.x`. Não há SLA nem suporte comercial, e alterações incompatíveis podem acontecer em releases menores — elas são registradas no [CHANGELOG](../CHANGELOG.md).
